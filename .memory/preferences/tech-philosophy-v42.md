# Victor42 技术哲学与系统架构偏好

## 1. 反向技术主义 (Reverse Technologism)

*   **定义**：不是反技术，而是先问"不用复杂技术是否更好"，只有当技术方案能显著降低人工时间或认知成本时才引入。
*   **核心维度**：审计只有两个主维度——**人工时间**和**认知成本**。其他因素不独立计入。
*   **派生指标**：
    *   **寿命**是单向领先指标：寿命短几乎必然推高人工时间（维修/更换）和认知成本（记着什么时候坏、坏了怎么办）；寿命长不是绿灯，只是没有红灯。
    *   **复杂度**通过寿命和故障排查心智负担间接影响主维度。
    *   **能源依赖和金钱成本**不独立计入，其影响已通过复杂度→寿命→主维度路径体现。
*   **决策规则**：如果一个方案在人工时间和认知成本两个维度上都不能带来净收益，其他维度再优秀也不引入。反之，如果在两个主维度上有显著净收益，其他维度的增加是可以接受的代价。

## 2. 赎回生活原则 (Redeeming Life via AI)

*   **底层规律**：AI 与自动化的本质属性是"时间赎回（赎买自由）"，而非"能力叠加（卷入竞争）"。
*   **洗碗机哲学**：接受机器不够完美，用容忍小瑕疵换取时间净收益。
*   **与反向技术主义的关系**：洗碗机哲学是反向技术主义通过审计的典型案例——在人工时间维度上有显著净收益，所以接受增加的复杂度作为合理代价。两者是同一条原则的两个面：反向技术主义守住下限（不降时间/认知成本就不引入），赎回生活向上优化（能省时间/认知成本就引入）。
*   **执行逻辑**：自动化脚本或 AI 代理的交付物，必须以"减少了多少人类维护时间"为第一衡量指标。
*   **高阶目标**：通过对低效循环的系统性熵减，将人类精力从"维护生存系统"中释放，投入到纯粹思考、审美和探索中。

## 3. 反脆弱架构 (Anti-Fragility)

*   **底层规律**: 系统设计优先考虑极端韧性，接受甚至拥抱外部冲击而非仅抵抗它。
*   **本地控制优先**: 优先保持本地控制能力和数据所有权，而非依赖专有、锁定的云平台。
*   **基础设施即代码**: 用 IaC 方式定义和恢复系统状态，降低单点故障和供应商锁定风险。
*   **去中心化永久性**: 数据存储和身份验证优先选择去中心化方案（如 IPFS、ENS），确保无法被单一实体阻断。

## 4. 被动接口优先 (Passive Interface)

*   **底层规律**：系统架构应遵循"被动接口"模式，避免主动产生未经请求的交互。
*   **认知守则**：尊重自然的信息衰减与遗忘规律。宁愿让非核心信息在静默中消失，也不构建会产生认知干扰的推送系统。
*   **工程判断**：自动化系统只有在显著降低长期维护时间时才值得引入。
