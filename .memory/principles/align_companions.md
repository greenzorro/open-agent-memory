# 对齐配套（Align Companions）

功能或修复已落地、需要同步测试与文档、用户说对齐配套 / 对齐文档 / 对齐测试 / align companions、或配套物仍用改动史语气时执行。不用于产品端到端验收、部署推送、或无行为变更的调研。

行为变更落地后，把目标根内**已有**配套物对齐到与代码一致的**现状**。配套物 = 后继读者（人或 Agent）用来理解、调用、验证当前行为的非核心实现：文档、测试、测试证据、面向读者的注释。

原则：

1. **盘点先于编辑。** 配套按角色存在；有则对齐，无则跳过。不为齐全发明新角色或新文件习惯。
2. **落盘只写现状。** 过程留在对话。文档与注释应可读作对本系统的首次说明。

本地与云端化身同一套：读本记忆执行，不依赖宿主是否安装了同名 skill。

## 配套角色

路径因仓而异；一文件可兼多角色，一角色可有多落点。

| 角色 | 职责 | 常见落点 |
|------|------|----------|
| **Agent 入口** | 能力、边界、如何把环境用到可调用 | 独立 AI 手册；README 内既有的 Agent 段；AI 向根 README；`SKILL.md` |
| **人类入口** | 定位、商店/安装链接、作者向合同 | README 人类段；双语 README |
| **维护备忘** | 现状真相源：结构、约定、坑、索引 | 根级或子项目 `notes` 类备忘 |
| **专题资料** | 单域深潜（部署、协议、视觉、API…） | `docs/`；模块级深潜文档；旁挂专题 md |
| **待办面** | 未完成事项的维护处（若仓有此分工） | 仓内既有的待办/计划类文件——已完成事项不写回此处 |
| **测试套件** | 锁住行为合同 | 各仓自定的测试目录与框架 |
| **测试证据** | 最近跑测结果与覆盖备注 | 与测试并列的报告；suite README 中的状态段；独立报告文件 |
| **实现旁注** | 不变量、API/解析合同、非显而易见的为何 | 注释、JSDoc、docstring |

README 内已有 Agent/人类分段时按其分段：用法进 Agent 段，维护深潜不进人类段。仓内若有 README 写作原则文档，从其规定。

容器仓中，在**发生行为变更的子项目**内盘点；父级无配套物时不要向上虚构。

## 目标根

对齐落在唯一的**目标根**（仓库根，或容器仓中的子项目根）。

1. **本轮点名** — 路径、项目名、或环境约定的别名 → 解析后采用。
2. **会话上下文** — 本对话正在改或刚改完的唯一代码树；反复读写的配套文件所属根。
3. **无法唯一确定** — 询问用户，给出 1–2 个候选及理由；确认前不开始盘点。

多目标时：列出范围请确认，或按指定顺序逐个做完；禁止混改多个根却只做部分自检。

## 工作流

```
1. 定目标 → 点名或上下文锁定目标根；否则询问
2. 定界   → 列出本次改变的可观察行为 / 合同
3. 盘点   → 目标根内各角色的实际路径
4. 测试   → 有套件则补用例、跑通、更新已有证据
5. 文档   → 按角色写入合同；删掉过时表述
6. 旁注   → 注释与实现一致
7. 自检   → 现状语气；未发明缺失角色
```

先锁定合同，再改文档：文档不得承诺代码未兑现的行为。步骤 4–6 可并行编辑。

某角色不存在 → 对应步骤整段省略。维护向事实写入该仓**实际承担**该职责的文件。

人类入口若由脚本生成（清单、安装段等）：对齐时运行生成器更新产物，不手改生成段；生成合同写在维护备忘与实现旁注。

### 测试与证据

- 沿用目标根既有目录与框架；覆盖新合同与必要回归。
- 只更新已有证据载体，保持其原有结构。
- 一则证据覆盖多文件时，按其既有范围更新。
- 无套件不新建测试；无证据习惯不新建报告文件。跑测即可，或写入已有载体。

### 同一事实只写一次

他处最多一句引用。

| 事实类型 | 优先角色 |
|----------|----------|
| 安装/调用、能力边界、一次性人机闸门 | Agent 入口 |
| 商店链接、作者向命名与文案合同、非 CLI 人工作业 | 人类入口 |
| 格式与协议变体、维护坑、指向测试/专题的索引 | 维护备忘 |
| 单域深潜 | 对应专题资料 |
| 字段级不变量、非显而易见的实现约束 | 实现旁注 |

原则可挖深；落盘宜短。CLI 细节以 `--help`（或等价）为源时，Agent 入口只留定位、I/O 形态与使用边界。

## 语气

禁止：修复/改为/之前/更新以支持；时间线变更表；排查过程入文档。

要求：直接陈述机制与合同。维护备忘指向测试与专题，不复述用例清单。

## 自检

- 目标根已锁定（点名、唯一上下文、或用户确认）
- 只编辑盘点中存在的角色与路径
- 有测试则已覆盖并跑通；有证据则已更新
- 合同按角色分流，无长段重复
- Agent 入口与人类入口未互相污染
- 读起来是现状说明，不是变更说明
- 未把端到端验证或部署并入本次对齐

## 禁止事项

1. 目标不明仍开工
2. 按想象中的标准文件集补齐缺失角色
3. 角色写错读者
4. 无套件却新建测试「凑配套」
5. 无证据习惯却新建报告文件
6. 手改由脚本生成的人类入口段
7. 旁注或文档写成变更记录
8. 改错容器仓层级（必须对准行为变更所在子树）
